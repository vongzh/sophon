# 智子 (Sophon) 车载系统安全与稳定性最高准则

> **适用平台**：吉利 / 魅族 FlymeAuto 智能座舱系统  
> **核心芯片**：芯擎科技 龙鹰一号 (DragonHawk 1 / SE1000) 7nm 车载芯片  
> **基准车型**：领克 08 (Lynk & Co 08) 及同平台车型 (领克07、银河E5等)  
> **文档效力**：**本项目最高架构铁律**。任何新功能开发、性能优化或代码提交，均不得违反本文档规定的三条绝对底线。

---

## 🛑 三条不可逾越的绝对底线

```
┌────────────────────────────────────────────────────────────────────────┐
│  底线一：绝不影响车机 (Zero Impact on IVI Performance & Stability)       │
│  底线二：绝不写入车机自带磁盘 (Zero Write to Internal Flash / UFS)         │
│  底线三：绝不修改系统原有设置与数据 (Zero Tampering with Vehicle Settings)  │
└────────────────────────────────────────────────────────────────────────┘
```

## 一、 底线一：绝不影响车机

车机首先是行车安全与车辆控制中枢，其次才是应用载体。本项目绝不以牺牲车机稳定性与流畅度为代价。

### 1.1 算力与资源隔离准则
- **全硬件编码，严禁 CPU 软编**：
  视频编解码必须 100% 采用龙鹰一号 VPU 硬件引擎（`MediaCodec` 硬件实例）。严禁使用 FFmpeg 或纯 CPU 软编码，确保应用运行期间 CPU 占用率控制在 8% 以下。
- **GPU 渲染按需休眠**：
  打灯补盲悬浮窗未激活时，OpenGL ES 渲染管线必须**完全挂起进入休眠态**，释放 GPU 渲染管线给 FlymeAuto 桌面、高德地图与 3D 渲染，严禁后台空转占用显存带宽。
- **严格内存限制与防泄漏**：
  Java 堆与 Native 显存总量严格限制在 150MB 以内，建立严格的 `Surface` 与 `SurfaceTexture` 生命周期回收机制，严禁因内存泄漏触发车机底层 OOM 杀进程。

### 1.2 行车安全避让准则
- **原厂 AVM / 倒车影像绝对避让**：
  挂入 R 挡或原厂 360 全景影像激活时，第三方向导悬浮窗必须在 **50ms 内无条件隐身**，不得与原厂安全影像争夺窗口图层。
- **沙箱级故障隔离**：
  多摄像头或编码器发生任何异常，必须在内部沙箱完成捕获与平滑降级，严禁向系统抛出未捕获异常导致车机底层服务连锁重启。

## 二、 底线二：绝不写入车机自带磁盘

领克 08 车机内部集成的高速 UFS 闪存是车机系统运行、地图包存储与未来 OTA 升级的命脉。持续擦写内部闪存会造成坏块磨损，甚至导致车机变砖。

### 2.1 存储控制规范：No USB, No Write
- **严禁向车机内置闪存写入音视频**：
  严禁向车机内部存储空间（包括 `/data/data/...`、`/sdcard/`、`/storage/emulated/0/`）写入任何录制的视频、切片或照片文件。
- **无外置 U 盘不启动录制**：
  当检测到车机未插入外置 USB 存储设备（U 盘或移动固态硬盘）时，录制引擎**强制保持就绪休眠态**。此时应用仅作为“纯打灯补盲悬浮窗”运行，不产生任何磁盘写入。
- **废除前代“中转写入”模式**：
  坚决摒弃 EVCam“先写内部存储、再拷贝至 U 盘”的做法。采用 **内存环形缓冲（Direct RAM -> USB Muxer）** 架构，编码后的数据仅在 RAM 中暂存必要的 GOP 块，直接流式写入外置 U 盘。若 U 盘拔出或写入严重卡顿，主动安全丢帧并告警，绝不向内部闪存溢出数据。

## 三、 底线三：绝不修改系统原有设置与数据

本项目仅作为车机的“纯感知助手”，不干涉、不改变车辆与系统的任何原有状态。

### 3.1 车身总线只读监听准则
- **单向只读（Read-Only Subscriber）**：
  通过 VHAL / CAN 通信捕获车身信号（转向灯、车门、车速）时，系统必须仅作为**事件订阅者**接入。
- **严禁向总线发送写指令**：
  严禁调用任何具有写权限或控制性质的底层 API，不得向车身控制器下发任何控制报文，确保车辆原有电子电气逻辑的绝对纯净。

### 3.2 系统配置零侵入
- **不修改系统 Settings**：
  不调用任何修改 `Settings.Global`、`Settings.Secure` 或 `Settings.System` 的代码，不强行修改车机的屏幕息屏策略、电池管理白名单或系统权限。
- **完全绿色无残留**：
  本应用所有配置仅保存在自身沙箱私有目录下（`Context.getSharedPreferences`）。用户卸载应用后，车机系统完全恢复原样，零脏数据、零底层注入残留。

## 四、 架构符合性核查清单 (Checklist)

每项代码在合并至主分支前，必须通过以下核查：

- [ ] 是否存在任何向内部存储路径写入大文件的调用？（一票否决）
- [ ] 录制模块在 U 盘拔出时是否立即停止落盘且不泄露到内部存储？（一票否决）
- [ ] 补盲悬浮窗在未显示时，OpenGL 线程是否完全进入 wait 挂起态？
- [ ] 车身信号监听类中是否存在任何 `setXXX` 或控制类方法？（一票否决）
- [ ] 原厂全景弹出时，悬浮窗是否在 50ms 内退出？
- [ ] 应用卸载后是否会对车机原有行为产生任何影响？
